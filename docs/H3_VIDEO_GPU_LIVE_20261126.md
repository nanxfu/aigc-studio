# H3 视频低成本云 GPU 实测（2026-11-26）

本轮实测完成：**单 RTX 3090 + 40GB 实例内临时磁盘**，基础 Q3 和 8-step Turbo Q4 各生成三条 480p/约5秒音视频，六条均通过文件契约校验。所有样片、日志和指标已取回；本轮两个实例均已销毁。销毁后复查的 Vast 当日分实例账单显示总支出 **$0.488**，其中真正生成视频的单卡实例为 **$0.406**，其磁盘费用 **$0.010**。

用户在执行中强调受众的存储支出，因此在下载模型前取消最初的双卡大盘配置，切换到单卡小文本端与临时盘。结果证明这条配置可生成视频；其是否满足用户的动作、音频与清晰度要求仍需继续评估。

## 成本调整

最初为 pi-H3 双卡 / 大组件准备创建了 2×4090 + 150GB 的临时实例。收到用户降低存储支出的要求后，已在上传模型前删除该实例，API 返回成功。它没有生成视频、没有下载 H3 权重；该实例当日账单为 **$0.082**（计算 $0.072、磁盘 $0.010），单列为本次调整的准备开销。

首轮改用已有预量化文件及小文本端，先验证整套约 16.7GiB 的路线。40GB 是实例自带申请容量，并非要求终端用户额外购买硬盘或长期维护模型卷。产品应保留“低频按次 / 免费 GPU”入口；不能将常驻大盘缓存当成受众的默认门槛。

同账号还有另一项已有 GPU 实验在运行，本轮没有修改它。费用查询已按本轮两个实例 ID 过滤，**不使用账号总余额下降估算本次消费**。下面的单条费用是按报价计算的估算；总费用与分项来自 `/api/v0/charges/` 账单返回。

## 实验口径

- 原始 H3 的量化 / 小文本端部署，以及融合 LightX2V 8-step LoRA 的 H3 量化衍生模型；不是 pi-H3、Pika 或 TriPRISM 的生成成绩。
- T2VA：832×480、124 帧、24fps，约 5.167 秒，含 32kHz stereo。
- 基础 Q3 为20步；Turbo Q4为8步并显式 video flow shift=12，audio shift沿用H3的3；均为Euler/discrete、CFG=1、seed=42，三条相同提示词（自然场景、产品、运动）。
- 当前 CLI 每次是新进程；耗时含加载、文本编码、采样、视频 / 音频解码和原生视频导出，MP4 转码单列。不能当作常驻服务热请求吞吐。
- 完成后 FFprobe 校验尺寸、帧数、帧率、音频采样率 / 声道；本机取回 MP4 后抽帧看质量。
- GPU 为整设备使用量采样，Linux RSS 和 cgroup v2 总内存独立报告。

## 准备期观察

权重下载已经完成，各文件下载时间合计约 76 秒；含校验的准备阶段为 85.62 秒。源码拉取、子模块和 CUDA 编译合计 **1,069.56 秒（17.83 分钟）**，与模型下载并行。完整源码和 CUDA 编译属于本次开发准备成本；面向用户部署应使用预编译引擎 / 镜像，不能让每个短任务反复编译。

额外准备 [ChrisColeTech 的 8-step Turbo GGUF](https://huggingface.co/ChrisColeTech/minimax-h3-turbo-GGUF)：已融合 LightX2V 8-step LoRA，Q4_K_M 主干 11,388,228,544 bytes，下载 44.96 秒并校验 SHA-256。它与基础 Q3 档共用文本端、视觉塔和两个 VAE，单套约 19.149 GiB。当前实验同时保留两份主干以便比较；面向用户只需要所选的一份。它是另一个衍生 checkpoint，不是同权重只改变步数的纯运行时 A/B。

GPU 初始化、模型下载、代码编译、实际生成和结果下载分别记录。基础档含校验的模型准备为85.62秒，Turbo只补主干下载约45秒；实际部署只下载选中的一套。源码与编译被保存为一次准备开销；尝试取回较大的原生编译二进制时传输超时，没有将不完整文件作为可部署发行物。

报告和六条样片已保存后删除本轮实例，随后查询返回 `instances=null`。销毁同时移除实例磁盘，没有遗留本轮收费存储。

## 结果

统一生成832×480、124帧、24fps、约5.167秒视频，带32kHz双声道音频。下面“总耗时”为CLI耗时加MP4转码，排除源码/模型下载、SHA-256读取与外部文件验证；每次是一个新CLI进程。

| 场景 | 基础 Q3，20步 | Turbo Q4，8步 | 基础 GPU 峰值 | Turbo GPU 峰值 |
| --- | ---: | ---: | ---: | ---: |
| 雪地狐狸 | 332.465s | 152.863s | 14,176 MiB | 16,684 MiB |
| 蓝色陶杯 | 323.237s | 149.063s | 14,176 MiB | 16,684 MiB |
| 纸飞机 | 323.415s | 149.274s | 14,176 MiB | 16,684 MiB |
| 三条中位数 | **323.415s（5.39min）** | **149.274s（2.49min）** | **13.84 GiB** | **16.29 GiB** |
| 按小时价估算的中位单条生成费 | **$0.024955** | **$0.011518** | | |

两组文件/音频契约均为3/3通过。本次Turbo整条速度约为基础档的**2.17倍**；这同时改变了checkpoint、量化档和采样步数，不能把它称作同一模型的运行时优化倍率。

基础档生成进程RSS峰值最高16.34GiB，Turbo最高18.43GiB。cgroup总量最高约48.42GiB，包含两个模型主干的文件页缓存和辅助进程。32GB RAM最低配置没有在本次验证，不能直接用进程RSS宣称32GB一定够。

## 质量与音频观察

- **狐狸**：两档都呈现雪地树林中行走的狐狸，五张抽帧中主体与环境较稳定。基础档偏暗，Turbo腿部动作和构图略有不同；没有BF16或原始32B文本端参考，不能判定量化损失大小。
- **产品**：蓝色陶杯、木桌、窗户和光影基本符合提示词；实际外观偏矮碗，仍需要更精确提示词与产品身份一致性测试。两档镜头变化较温和。
- **运动**：纸飞机完成教室内飞行和靠近桌面的内容，但机翼/折纸几何在抽帧中明显变化，尤其Turbo版本。这条难例的动作/形状稳定性不能判为合格。
- **音频**：六条文件都有非静音AAC stereo音轨，格式正确；没有人工完整听审，不能据此证明音效与动作同步。三条基础档的mean/max音量分别为狐狸−42.8/−26.0dB、产品−13.0/−1.2dB、运动−38.4/−23.5dB；Turbo为−43.1/−29.7dB、−13.7/−1.1dB、−48.5/−21.3dB，响度差异明显。

本次的“6/6通过”是技术产物验收，**不是6条都达到了成片质量**。尤其多参考、首尾帧、中文对白、768p与更长视频尚未实测。

**2026-11-26 产品决策修订**：暂缓自动租机的Vast Provider，不将“开机→下载→生成少量内容→销毁”作为低频用户的默认入口，也不以长期租模型卷作为必要条件。Vast可继续用于工程验证，已有环境的用户通过普通`private-worker`接入。先评估现有按次API及Kaggle/Colab可用资源的完整成本和能力；其它平台同样须计入冷启，不因Vast不适用就假定它们必然便宜。单卡/量化推理本身的成功证据与平台选择分开保留。
