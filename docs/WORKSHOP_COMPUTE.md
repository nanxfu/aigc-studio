# 工坊执行位置

PBR 根据本机硬件检测选择默认执行位置。满足条件时优先本地，用户可以通过参数区的「本地 / 云端」胶囊切换，选择保存在本机。硬件检测迟到时只更新自动默认值，不覆盖用户已经选定的云端位置。

本地 PBR 当前支持 Windows / Linux x64 与 NVIDIA CUDA。默认基线由 `shared/workshop-compute.js` 维护：8 GB 级显卡、至少 5 GiB 空闲显存、16 GB 级系统内存与至少 4 GiB 空闲内存，首次准备时模型盘至少有 12 GiB 可用空间。显卡和系统内存允许少量固件预留；未知配置、多块小卡、非 CUDA 设备都不能被认定为可用。环境与模型已缓存后，磁盘仅需保留 1 GiB 运行余量。任务执行前重新检测资源，条件变化时返回可读错误，用户可切换云端重试。

本地运行使用独立 Python 3.11 环境，不改系统 Python。首次使用优先调用已有 uv，否则下载并校验固定版本的 uv，再准备 PyTorch CUDA、diffusers 和相关依赖。两套 Marigold 权重共约 5.16 GB，固定仓库版本，缓存于本机模型目录的 `marigold/`；Python 环境位于应用数据目录的 `runtime/local-pbr/`。材质通道与法线依次推理，启用 CPU offload，进程结束后释放资源。

本地任务进入既有串行队列，支持取消与退出清理，四通道仍保存为同一条复合资产和版本树。任务元数据记录实际设备和执行来源。云端 PBR 使用当前 Kaggle / Colab / SaladCloud / 私有 Worker 来源；当前生图来源是商业 API 或 Vulkan 时，PBR 使用 Kaggle，不改生图设置。

抹除背景没有执行位置或云端模型选择。直接使用已有的本机 RMBG-1.4 模型，优先 WebGPU FP16，失败或不可用时回退 WASM INT8。界面保留首次下载量和模型许可说明。

验证包括硬件边界、多卡判断、任务提交、真实子进程协议、环境缓存、取消、四通道归档和界面选择状态。当前开发机没有 NVIDIA CUDA，新增本地链路尚未完成真实 GPU 的性能与画质验收；检测基线是保守默认值，并非已经实测的最低硬件要求。
